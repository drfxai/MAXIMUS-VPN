# تکمیل مسیرهای انتقال — ۲۳ اکتبر ۲۰۲۶

نسخهٔ عمومی 1.0.2، کد داخلی Android برابر 34.

## مسیرهای قابل استفاده در برنامه

| قابلیت | پیاده‌سازی و محل استفاده |
|---|---|
| SNI/Host | Lab → Transport tools؛ ساخت پروفایل VLESS، VMess یا Trojan روی WebSocket/TLS با IP، SNI و Host مجزا؛ حفظ اعتبارسنجی گواهی و اعتبارنامهٔ پروتکل |
| تقسیم دست‌دهی | گزینهٔ Native Xray TLS record + TCP fragmentation در همان فرم؛ استفاده از موتور واقعی و موجود Xray |
| Spoof Tunnel | Servers → Maximus Tunnel → Spoof carrier؛ لولهٔ UDP با حامل خام بین دو سرور، با Hysteria2 رمزگذاری‌شده و احرازشده درون آن |
| L3 candidate scanner | هنگام راه‌اندازی حامل TCP/ICMP، گیرنده ابتدا آماده می‌شود، سپس چهار بسته برای هر IP صریح ارسال می‌شود؛ آزمون در هر دو جهت، حداکثر ۱۶ IP برای هر جهت |
| Spoofed carriers | انتخاب مستقل TCP، UDP، ICMP و ICMPv6 برای ارسال و دریافت؛ اجرا روی دو سرور Linux، بدون نیاز به روت گوشی |
| DNS jitter | patch بومی dnstt و سقف QPS قبلی حفظ شده؛ موتور در APK رسمی بسته‌بندی می‌شود |
| Clean-IP | تأیید چالش واقعی WebSocket، محدودیت اندازهٔ هدر و رد پاسخ ناقص/مبهم؛ بررسی تغییر شبکه بین دسته‌های اسکن و پیش از تحویل نتیجه |
| ثبت WARP با fragment | بازقالب‌بندی اولین ClientHello به رکوردهای کوچک TLS؛ حفظ transcript و اعتبارسنجی TLS؛ پاسخ API با اندازهٔ محدود خوانده می‌شود |

## پیش‌نیاز حامل سمت سرور

دو سرور مدیریت‌شده با IPv4 عمومی، SSH با fingerprint تأییدشده، Linux/systemd و root یا sudo بدون رمز لازم‌اند. کاربر IPهای مبدأ را صریح وارد می‌کند. دامنه، CIDR یا اسکن خودکار اینترنت پذیرفته نمی‌شود. ارائه‌دهنده باید ارسال بسته با مبدأ انتخابی را اجازه دهد؛ مسدودبودن این امکان با تغییر نرم‌افزار گوشی برطرف نمی‌شود.

هستهٔ Apache-2.0 پروژهٔ ParsaKSH/spoof-tunnel در نسخهٔ `v3.1.0-beta.0` با SHA-256 مستقل برای amd64 و arm64 نصب می‌شود. اسکریپت شبکه‌ای اجرا نمی‌شود؛ سرویس با محدودیت قابلیت `CAP_NET_RAW` اجرا می‌شود. پورت UDP ورودی برنامهٔ حامل فقط روی loopback است. احراز هویت، اعتماد به گواهی و رمزگذاری توسط Hysteria2 درون لوله انجام می‌شود.

تستر upstream فقط TCP و ICMP را پشتیبانی می‌کند؛ برای UDP/ICMPv6 مرحلهٔ اسکن ادعا نمی‌شود. مشاهدهٔ بسته در تست خام نیز اثبات اتصال اینترنت نیست. نصب حامل زمانی پذیرفته می‌شود که درخواست HTTPS از تونل عبور کند و خروجی خارجی مشاهده شود. در غیر این صورت بازگردانی انجام می‌شود؛ شکست SSH هنگام بازگردانی باید در همان گزارش مشخص شود. هیچ مسیر مستقیم اینترنتی برای جایگزینی شکست تونل اضافه نشده است.

## اعتبارسنجی

- ۳۴ آزمون JVM مربوط به تنظیمات تونل، اسکریپت‌ها، نگهداری اعتبارنامه، fronting، Clean-IP و WebSocket در محیط محلی موفق شدند.
- ۲۵٬۰۶۲ بررسی DNS و ۵۳ بررسی TLS، شامل تبادل واقعی TLS محلی، fragmentation و رد گواهی/نام میزبان، موفق شدند.
- workflow جدید Spoof carrier integration حامل‌ها را در namespaceهای شبکهٔ جدا و بدون اسکن اینترنت بررسی می‌کند.
- آزمون کامل Android و lint باید روی همین تغییرات در CI موفق شود؛ نتیجهٔ انتشار جداگانه ثبت خواهد شد.
- آزمون گوشی فیزیکی و اپراتورهای ایران انجام نشده است. نتیجهٔ آزمایش namespace یا emulator را نباید نتیجهٔ فیلترینگ واقعی دانست.

SNI/Host separation و تقسیم TLS به سازگاری سرور/مسیر نیاز دارند؛ هویت اپراتور موبایل را جعل نمی‌کنند. fragmentation این نسخه در لایهٔ TLS/TCP است، نه fragmentation بستهٔ IP.
