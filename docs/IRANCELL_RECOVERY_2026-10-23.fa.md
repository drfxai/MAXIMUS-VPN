# اصلاح بازیابی پس از گزارش ایرانسل — کد ۳۵

مبنای بررسی، گزارش واقعی نسخهٔ ۳۴ روی SM-F711B و شاخهٔ اصلی GitHub است. فایل ZIP قدیمی کد ۳۱ مبنای اصلاح نیست.

- Tor پذیرفته‌شده پیش از پایان بودجه، تا سقف ۴۲۰ ثانیه برای راه‌اندازی و دو درخواست فرصت دارد. مهلت داخلیِ توقف پیشرفت و سقف شش‌دقیقه‌ای راه‌اندازی حفظ شده‌اند. مهلت بیرونی دیگر فرصت داخلی را در ۷۸ ثانیه قطع نمی‌کند. توقف کاربر همچنان coroutine و فرایندها را متوقف می‌کند.
- خطای صریح ثبت‌نام موتور از خروجی محدود بومی حفظ می‌شود. در همان جست‌وجو، حالت‌ها و زنجیره‌های وابسته به همان موتور دوباره ثبت‌نام نمی‌کنند. شکست Matrix به MASQUE تعمیم داده نمی‌شود چون کلاینت ثبت‌نام متفاوت است. شکست صرف ترافیک نیز باعث مسدودسازی ثبت‌نام نمی‌شود.
- سلامت از دو مقصد مستقل HTTPS با همان VPN یا SOCKS احرازشده آزمایش می‌شود. ریدایرکت موفقیت محسوب نمی‌شود؛ گواهی معتبر لازم است. این بررسی همچنان اثبات پایداری طولانی نیست.
- برای حداکثر دو مبدأ TLS موجود، چهار گزینهٔ Fake SNI با TTLهای ۴ و ۸ ساخته می‌شود. DNS همان مسیر محافظت‌شدهٔ برنامه را دارد؛ IPv4 عمومی و TLS معتبر لازم است؛ credential و SNI و Host حفظ می‌شوند. گزینه‌ها تنها با دو درخواست واقعی تأیید می‌شوند. تنظیم TTL تضمین اتصال نیست و این گزینه برای همهٔ کانفیگ‌ها کاربرد ندارد.
- خطای یک TTL یا پل Tor، با نام کلی موتور به همهٔ TTLها یا پل‌های دیگر تعمیم داده نمی‌شود. نتیجهٔ بازیابی هنگام تغییر شبکه دور ریخته می‌شود.
- پیام MTU می‌گوید کاهش اندازه مشکل آزمون را حل نکرده، نه اینکه علت را قطعاً رد کرده است. بایت‌های نوشته‌شده به سوکت آپلود به‌عنوان دریافت تأییدشدهٔ مقصد گزارش نمی‌شوند.

آزمون‌های رگرسیون: بودجهٔ Tor، محدودسازی وابستگی ثبت‌نام، حفظ علت خطا توسط EngineReaper، هویت و محدودهٔ Fake SNI، مقصد جایگزین سلامت و رد ریدایرکت. آزمون فیزیکی اپراتور پس از نصب هنوز لازم است. شکست API ثبت‌نام، سرور اشتراک یا مسیر اپراتور صرفاً با این اصلاحات رفع‌شده اعلام نمی‌شود.
